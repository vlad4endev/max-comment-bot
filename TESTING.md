# Тестирование бота MAX

Подробный сценарий ручной проверки основного потока: старт из диплинка, комментарий, уведомление администратора, ответ пользователю.

## Что понадобится

- **Node.js** версии 18 или новее.
- **Два аккаунта MAX**: обычный пользователь (тестирует бота) и аккаунт администратора, чей числовой идентификатор чата указан в `ADMIN_CHAT_ID` (на него приходят уведомления о новых комментариях).
- Файл **`.env`** в корне проекта (ориентир — `config/.env.example`):
  - `BOT_TOKEN` — токен бота из кабинета MAX.
  - `BOT_NICKNAME` — ник бота без `@`, как в URL `https://max.ru/{ник}`.
  - `ADMIN_CHAT_ID` — ID чата администратора в MAX (число), куда бот шлёт уведомления о комментариях.
  - Режим событий: по умолчанию в **development** используется **long polling** (`MAX_RECEIVE_MODE` не задан или `polling`). Для **webhook** задайте `MAX_RECEIVE_MODE=webhook`, полный `WEBHOOK_URL` (https) и в production — `WEBHOOK_SECRET` (см. [POST /subscriptions](https://dev.max.ru/docs-api/methods/POST/subscriptions)).

## Предусловие: запуск бота

1. Установите зависимости (один раз): `npm install`.
2. Заполните `.env` корректными значениями.
3. Запустите бота в режиме разработки:

   ```bash
   npm run dev
   ```

4. В консоли дождитесь цепочки сообщений инициализации и в конце строки:

   - при **polling**: **`🤖 Бот работает и ждёт события`** (после «Запуск бота (long polling, GET /updates)...»);
   - при **webhook**: **`Подписка webhook активна (POST /subscriptions)`** и сообщение о том, что HTTP слушает порт (например `POST /webhook`).

   Перед этим обычно видны «Инициализация бота», «Обработчики событий зарегистрированы».

5. Оставьте терминал открытым: по ходу тестов вы сверяете **ожидаемые логи** (см. ниже). Логгер пишет время в ISO-формате, уровень `[INFO]` и сам текст сообщения; часть вызовов дополнительно выводит второй аргумент (объект с полями вроде `postId`, `userId`).

---

## Тест 1: событие `bot_started` (вход по диплинку с постом)

**Цель:** убедиться, что при старте с payload `post_<id>` бот переводит пользователя в режим комментирования к этому посту и просит текст комментария.

### Шаги

1. **Сформируйте диплинк** под свой бот и пост (пример для поста `1054`):

   `https://max.ru/{BOT_NICKNAME}?start=post_1054`

   Подставьте вместо `{BOT_NICKNAME}` значение из `.env` без фигурных скобок (как в `config/.env.example`: это ник в URL MAX).

2. Откройте ссылку **в браузере** на компьютере или телефоне, где установлен MAX.

3. Нажмите **«Открыть в MAX»** (или аналогичную кнопку открытия в приложении).

4. В чате с ботом нажмите **«Начать»** / начните диалог, чтобы сработало событие старта с переданным `start`-параметром.

### Ожидаемый результат в MAX

Бот отвечает сообщением:

**`📝 Напишите ваш комментарий. Я передам его автору канала.`**

### Ожидаемый результат в консоли

Строка вида:

**`bot_started: пользователь <числовой_user_id>`**

где `<числовой_user_id>` — идентификатор пользователя MAX, открывшего бота.

## Тест 2: отправка комментария

**Цель:** комментарий сохраняется, админ получает уведомление в личку, пользователь видит подтверждение, состояние «комментирование» сбрасывается.

### Предусловие

Вы прошли **Тест 1** и видите запрос написать комментарий (режим комментирования активен).

### Шаги

1. От **того же** пользователя отправьте боту произвольный текст, например: **`Отличный пост!`**

### Ожидаемый результат в MAX (пользователь)

Бот отвечает:

**`✅ Спасибо! Ваш комментарий отправлен на модерацию.`**

### Ожидаемый результат в MAX (администратор)

На аккаунт, соответствующий **`ADMIN_CHAT_ID`**, в личные сообщения от бота приходит уведомление с текстом о **новом комментарии** (пост, автор, текст) и кнопкой **`✉️ Ответить`**.

### Ожидаемый результат в консоли

По порядку (между ними могут быть другие служебные строки):

1. **`message_created: от <user_id>`** — входящее сообщение от пользователя.
2. **`Комментарий создан: <uuid>`** — внутренний идентификатор созданной записи.
3. **`Уведомление отправлено админу`** — во второй строке/аргументе лога обычно видны `postId` и `userId`.

Если отправка админу не удалась, в консоли будет **`ERROR`** с текстом про невозможность отправить уведомление админу — в этом случае проверьте `ADMIN_CHAT_ID` и права бота.

## Тест 3: ответ администратора пользователю

**Цель:** по нажатию «Ответить» админ переходит в режим ответа; после текста ответа пользователь получает уведомление в личку.

### Предусловие

Выполнен **Тест 2**, в чате админа есть уведомление с кнопкой **`✉️ Ответить`**.

### Шаги

1. Войдите в MAX **под аккаунтом администратора** (тот же, что в `ADMIN_CHAT_ID`).

2. В уведомлении о комментарии нажмите **`✉️ Ответить`**.

3. Убедитесь, что бот в **личке с админом** просит ответ:

   **`📝 Напишите ответ на комментарий.`**

4. Отправьте текст ответа, например: **`Спасибо за отзыв!`**

### Ожидаемый результат в MAX (админ)

Бот отвечает админу:

**`✅ Ответ отправлен пользователю.`**

### Ожидаемый результат в MAX (пользователь)

Пользователю, который оставлял комментарий, в личку от бота приходит сообщение в формате:

**`💬 На ваш комментарий ответили:`**  
далее перенос строки и цитата ответа в кавычках, например **`"Спасибо за отзыв!"`**.

### Ожидаемый результат в консоли

- После нажатия кнопки: строка с **`message_callback:`** и **`payload=reply_<user_id>`** (ID пользователя, которому админ отвечает).
- После отправки текста ответа админом: снова **`message_created:`** от ID админа.
- После успешной отправки пользователю: **`Пользователю отправлено уведомление об ответе`** (рядом в логе — объект с **`userId`** комментатора).

## Проверка логов и ошибок

- **Успех:** для каждого шага сценария в консоли есть ожидаемые **`[INFO]`**-сообщения, нет неожиданных **`[ERROR]`** после действий в MAX.
- **Ошибки:** при **`[ERROR]`** разверните вывод в терминале целиком — для ошибок логгер выводит второй аргумент (часто стек или объект от API). По стек-трейсу видно файл и строку; по тексту сообщения — причина (токен, ID чата, сеть и т.д.).
- **`[DEBUG]`** в development может дополнять картину; в production по умолчанию debug может не выводиться (`NODE_ENV`).

## Краткий чеклист

| Шаг                         | MAX (пользователь)     | MAX (админ)     | Консоль                                      |
|----------------------------|------------------------|-----------------|----------------------------------------------|
| Диплинк `post_…` + Начать  | Запрос комментария     | —               | `bot_started: пользователь …`              |
| Текст комментария          | Спасибо, модерация   | Уведомление + кнопка | `Комментарий создан`, `Уведомление отправлено админу` |
| Ответить → текст ответа  | Ответ в личке        | «Ответ отправлен» | `message_callback`, `Пользователю отправлено уведомление об ответе` |

Если какой-то пункт чеклиста не выполняется, зафиксируйте точное сообщение в MAX и последние строки консоли — это ускорит разбор проблемы.
